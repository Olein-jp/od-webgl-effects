# 設定と保存データ（Issue #2）

保存属性は従来どおり `odWebgl.version = 1`。バージョン省略時は1として扱い、既存ブロックの書き換えや一括移行は行わない。

| データ | 責務と検証 |
| --- | --- |
| `version`, `enabled`, `effect` | バージョン1、厳密な真偽値、`schemas/effects.json` のID許可リスト |
| `settings` の共通項目 | `schemas/common.json` の速度・強度・不透明度、2〜5色のパレット |
| `settings` の固有項目 | `schemas/effects.json` の各エフェクトのコントロールと既定値 |
| `preset` | 設定に付随する選択ID。描画時に再適用せず、保存された `settings` を使用。空文字はカスタム |
| `performance` | 品質・モバイル品質・1〜60 FPS・静止フラグ。エフェクトやプリセット切替で維持 |
| `fallback` | 背景色。エフェクトやプリセット切替で維持 |

PHPの `Settings::sanitize_settings()` とJSの `sanitizeSettings()` は7種類の型を同じ規則で検証する。`range` / `number` は有限の数値のみを受け付け、数値文字列・真偽値・NaN / Infinityは既定値へ戻す。範囲外の数値は上下限に制限する。`toggle` は真偽値のみ、`select` は選択値との厳密一致のみ受け付ける。`color` / `colorPalette` とパレットは3桁・6桁HEXまたは `var(--wp--preset--color--slug)` の参照だけを受け付ける。`text` はプレーンテキストとしてUnicodeコードポイント200文字まで保持する。型の不一致は既定値へ戻す。

パレットは配列に限定し、2色未満は共通の既定3色へ戻す。6色目以降は破棄、不正な色は `#01273e` へ戻す。未知のトップレベルキー・固有キー・スキーマにない既定値は検証結果へ引き継がない。GLSLや実行コードを評価する経路はない。

PHPの `Settings::sanitize()` とJSの `sanitizeConfig()` は無効状態も検証できる。描画用の `normalize()` はさらに `enabled === true` を要求する。エディターもサーバーも同じ同梱定義を参照する。外部登録APIの互換性保証はPhase 3で扱う。

未知バージョン・未知エフェクトは描画しない。既存のCSS背景色フォールバックと警告表示を利用し、保存された元属性は明示的な操作まで書き換えない。

## 切替と履歴

- エフェクト切替: 色・速度・強度・不透明度を維持し、切替先の固有項目を既定値へ戻す。前の固有項目は捨てる。プリセットIDは空にする。
- 同梱プリセット: 切替先エフェクトの既定値にプリセットを重ね、再検証する。共通設定もプリセットの指定・既定値へ戻す。色は指定がなければ共通パレットへ戻す。
- 手動変更: プリセットIDを空にしてカスタム状態にする。
- 各変更を1回の `setAttributes()` で反映し、WordPress標準のUndo/Redoで属性全体を復元する。独自の履歴ストアは持たない。
- 元の保存ブロックコメントは閲覧だけでは変更しない。通常の編集・保存時もバージョン1を維持する。

## 検証

`tests/fixtures/settings.json` の同一入力・期待値をJestとPHPの両方で検証する。全型、テーマ参照、不正値、未知バージョン、未知キー、Unicode、旧属性を対象にする。WordPress統合テストでも実際のサニタイザー、各エフェクトID、ブロックのシリアライズ、サーバー出力を検証する。

ブラウザテスト `backgrounds.spec.js` は保存・再編集の完全一致、サーバー設定との一致、Undo/Redoを対象にする。今回のセッションでは検証サーバーのlistenが拒否されたため、追加ブラウザテストは未実行。Issue #2の完了判定には実行が必要。
